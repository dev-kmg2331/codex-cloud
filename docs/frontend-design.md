# 프런트엔드 디자인 가이드

웹 애플리케이션에서 사용자가 현재 위치와 상태를 파악하고 다음 작업을 쉽게 선택할 수 있도록 화면을 설계한다. 조회, 입력, 설정, 데이터 시각화에 공통으로 적용할 기준을 다룬다. 제품의 브랜드, 언어, 정보 밀도에 맞게 시각 값을 조정하고, 같은 역할을 하는 요소에는 같은 표현과 동작을 사용한다.

## 화면 구조와 정보 배치

- 전역 탐색, 서비스 전체 상태, 현재 화면의 콘텐츠를 구분한다. 탐색에서 현재 위치를 표시하고, 화면 상단에는 제목과 해당 화면의 주요 작업을 배치한다. 설명은 제목만으로 알기 어려운 범위나 조건이 있을 때 추가한다.
- 사용자가 결정하는 순서대로 정보를 배치한다. 목록은 검색 조건 → 결과 → 페이지 이동, 대시보드는 기간과 범위 → 요약 → 추이와 상세, 편집 화면은 항목별 입력 → 변경 내용 확인 → 저장 순으로 구성한다.
- 관련 항목은 제목이 있는 구역으로 묶는다. 중립 배경 위에 경계선으로 구분한 패널을 사용하고, 같은 구역 안에서는 여백으로 정보의 관계를 표현한다. 열이 많아도 본문이 과도하게 늘어나지 않도록 화면 유형에 맞는 최대 폭을 정한다.

## 색상과 타이포그래피

색상과 크기는 역할별 이름을 붙인 공통 값인 디자인 토큰으로 관리한다. 예를 들어 주요 버튼과 선택된 탐색은 같은 강조 계열을 쓰고, 본문과 보조 텍스트는 읽는 순서에 맞게 대비를 조정한다. 오류, 경고, 성공은 짧은 상태 문구를 함께 표시한다.

| 항목 | 적용 기준 | 시작값 예시 |
| --- | --- | --- |
| 배경과 표면 | 페이지와 패널을 서로 다른 명도로 구분한다. | 페이지 `#F3F5F7`, 패널 `#FFFFFF` |
| 텍스트와 경계 | 본문과 보조 텍스트를 구분하고, 표면에 실제로 놓이는 조합의 대비를 확인한다. | 기본 텍스트 `#182230`, 경계선 `#DCE3EC` |
| 강조와 위험 | 주요 동작과 포커스를 일관되게 표현하고, 삭제 등 위험한 동작은 별도 색상 역할로 구분한다. | 강조 `#2457C5`, 위험 `#BE3344` |
| 서체와 숫자 | 기본 서체와 대체 서체를 지정한다. 표와 지표에서 자릿수를 비교할 때는 고정 폭 숫자(`tabular-nums`)를 사용한다. | 본문 14px, 줄 높이 1.5, 제목 29px, 섹션 제목 16px |
| 간격과 모서리 | 아이콘과 라벨, 컨트롤 내부, 패널 내부, 패널 사이의 간격을 각각 공유한다. | 패널 내부 16–22px, 공통 반경 4·6·9px |

위 값은 밀도가 높은 관리 화면을 위한 예시다. 본문과 보조 문구의 크기, 대비, 조작 영역은 대상 화면과 사용 환경에서 확인한다. 한 가지 예외 때문에 새 토큰을 만들기 전에 기존 역할로 표현할 수 있는지 살핀다.

## 공통 컴포넌트와 화면 패턴

| 패턴 | 적용 기준 |
| --- | --- |
| 버튼과 링크 | 가장 중요한 동작에만 강조 버튼을 사용한다. 보조 작업은 강도를 낮추고, 다른 위치로 이동하는 링크에는 목적지를 드러낸다. 버튼 이름은 ‘저장’, ‘다시 조회’처럼 결과를 예상할 수 있게 쓴다. 아이콘만 있는 버튼에는 접근 가능한 이름을 준다. |
| 입력과 필터 | 입력마다 라벨을 두고 단위, 제약, 오류는 해당 입력 가까이에 표시한다. 필터가 즉시 적용되는지 ‘조회’로 적용되는지 알 수 있게 하고, 적용한 범위를 결과에서 확인할 수 있게 한다. 검색 조건이 바뀌면 첫 페이지에서 결과를 보여준다. |
| 표와 페이지 이동 | 열 제목과 데이터의 관계가 있는 표 구조를 사용한다. 같은 단위의 수치는 오른쪽에 정렬하고, 행의 상세 열기처럼 클릭 가능한 동작은 버튼이나 링크로 표시한다. 현재 페이지, 결과 건수 또는 전체 페이지 수, 이동 가능 여부를 보여준다. |
| 상태 배지 | 짧은 문구로 ‘대기’, ‘처리 중’, ‘완료’, ‘실패’를 구분한다. 상태를 보여주는 배지와 상태를 변경하는 버튼은 조작 가능 여부가 드러나게 디자인한다. |
| 요약 지표와 차트 | 지표는 이름, 값, 단위를 묶고 필요한 경우 기간이나 집계 범위를 덧붙인다. 차트의 축과 범례에 단위를 표시하고, 계열은 라벨과 색상 또는 선 모양으로 구분한다. 표시 항목을 토글하면 범례와 툴팁에도 같은 선택을 반영한다. 주요 값은 요약이나 표에서도 확인할 수 있게 한다. |
| 상세 보기와 대화상자 | 목록 맥락에서 확인할 짧은 상세나 결정을 대화상자에 둔다. 제목, 필요한 설명, 닫기, 확인 작업을 제공한다. 화면을 닫으면 사용자가 보던 목록과 검색 조건을 이어서 사용할 수 있게 한다. |

기본 버튼, 입력, 배지, 대화상자는 공통 컴포넌트로 두고, 페이지 제목, 필터, 표, 상태 안내는 화면에서 조합한다. 색상, 크기, 포커스 같은 공통 동작은 공유 컴포넌트에서 관리하고 화면은 표시할 내용과 업무 상태를 전달한다.

## 비동기 상태와 저장

| 상태 | 사용자에게 보여줄 내용 |
| --- | --- |
| 처음 불러오는 중 | 불러오는 대상을 문장으로 알려 준다. 표나 차트는 실제 콘텐츠와 비슷한 크기의 자리 표시자를 사용해 전환 시 화면 이동을 줄인다. |
| 갱신 중 | 같은 범위를 다시 조회할 때는 기존 결과를 유지하고 갱신 중임을 표시한다. 검색 범위가 바뀌었는데 이전 결과를 잠시 표시할 경우, 사용자가 그 결과를 새 조건의 결과로 해석하지 않도록 구분한다. |
| 결과 없음 | ‘아직 기록이 없습니다’와 ‘검색 조건에 맞는 결과가 없습니다’를 구분하고, 상황에 맞게 항목 추가나 조건 변경을 안내한다. |
| 오류 | 실패한 동작과 사용자가 할 수 있는 다음 작업을 안내한다. 다시 시도할 수 있는 조회에는 결과 영역에 재시도 버튼을 둔다. 갱신에 실패해 이전 데이터를 유지하면 마지막 갱신 시점을 표시한다. |
| 처리 중 | 실제 진행률을 알 수 있으면 수치로 표시한다. 진행률을 알기 어려우면 ‘파일을 처리하는 중입니다’처럼 현재 작업을 설명한다. 진행 중인 작업의 중복 제출을 막는다. |

자동 갱신은 진행 중인 요청이 끝난 뒤 다음 주기를 시작한다. 새 검색을 적용하면 지연된 이전 검색을 취소하고 이전 응답이 현재 결과를 덮어쓰지 않게 한다.

설정 화면에서는 작성 중인 값, 저장된 값, 현재 적용된 값을 필요한 경우 구분한다. 저장 후 즉시 적용되는지 또는 별도 절차가 필요한지 저장 전에 안내한다. 영향이 큰 변경은 바뀌는 값과 영향을 확인할 수 있게 하고, 저장 실패 시에는 입력을 유지한다. 저장하지 않은 작업이 사라지는 화면 이동에는 계속 편집할 수 있는 선택을 제공한다.

## 좁은 화면과 동작

- 탐색, 필터, 차트 열은 내용이 읽기 어려워지는 폭에서 재배치한다. 좁은 화면에서는 한 열로 쌓고, 중요한 작업은 본문에서 접근할 수 있게 유지한다. 표처럼 가로 비교가 필요한 콘텐츠는 해당 영역 안에서 스크롤한다.
- 필터나 작업 영역을 고정할 때는 입력값과 포커스를 유지한다. 화면 높이가 작아 본문이나 포커스가 가려지면 고정을 해제하거나 위치를 조정한다.
- 전환 효과는 페이지 이동, 대화상자 열기, 버튼 누름처럼 사용자의 조작에 짧게 반응하도록 사용한다. 주기적 데이터 갱신에서는 화면 진입 효과를 반복하지 않는다. `prefers-reduced-motion` 환경에서는 이동과 반복 효과를 줄이고 상태 문구는 유지한다.

## 접근성과 구현 검토

화면을 완성한 뒤 대표 작업을 마우스, 키보드, 좁은 화면에서 각각 수행해 본다. 자동 검사와 함께 다음 항목을 직접 확인한다.

- 키보드로 탐색, 입력, 제출, 상세 열기와 닫기를 수행할 수 있다. 포커스가 보이고 고정 영역에 가려지지 않으며, 대화상자를 닫으면 열었던 위치로 돌아온다. 드래그나 차트 확대에는 키보드나 버튼 등 다른 조작 방법도 제공한다.
- 입력의 라벨과 오류가 보조 기술에 연결되고, 중요한 로딩·저장 결과가 필요할 때 전달된다. 색상에 의존하지 않고 상태를 구분할 수 있다.
- 좁은 화면과 확대 환경에서 내용이나 작업 버튼이 잘리지 않는다. 긴 라벨, 큰 수치, 긴 오류 문구와 빈 결과에서도 배치를 확인한다.
- 실제 배경 위 텍스트 대비를 확인한다. WCAG 2.2 AA의 일반 텍스트 대비는 최소 4.5:1이고 큰 텍스트는 최소 3:1이다. 컨트롤의 경계와 상태 표시, 포인터 조작 영역은 각각 해당 기준과 예외를 확인한다. [WCAG 2.2](https://www.w3.org/TR/WCAG22/)

## RTSP Live 적용 기준

- 관제 화면은 4·9·16분할 영상 그리드를 중심으로 배치한다. 상단에는 전체 bbox와 하드웨어 가속을, 개별 타일에는 해당 영상의 bbox와 종료 동작을 배치한다. 선택된 타일을 표시해 카메라를 열기 전에 재생 위치를 확인할 수 있게 한다.
- 넓은 화면에서는 카메라 목록을 영상 오른쪽에, 좁은 화면에서는 영상 아래에 둔다. 카메라를 끌어 놓거나 선택 후 버튼으로 배치할 수 있어야 한다.
- 연결 중, 재생 중, 연결 실패를 타일에 표시한다. 카메라 목록의 첫 조회, 검색 결과 없음, 갱신 실패에는 각 상태에 맞는 문구를 사용한다.
